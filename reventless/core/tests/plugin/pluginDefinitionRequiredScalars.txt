# Every bare required scalar reachable from `pluginDefinition`, sorted.
#
# This file is a tripwire, not an inventory to keep tidy. Everything reachable from
# `pluginDefinition` is persisted in the Plugin lifecycle aggregate's event log, and a
# scalar is the one shape `Message.fillMissingDefaults` cannot derive a value for: adding
# one means every message stored before it decodes with a value this framework invented
# (`""` / `0` / `false`), reported at runtime as a warning and nowhere else.
#
# So a diff here is a design decision, not a chore. If your new field can be absent, give
# it the `js_nullable` (`T | null`) shape and this list does not change. If it genuinely
# must be a required scalar, add the line and accept that older payloads carry a fabricated
# value for it.
#
# Regenerate ONLY after making that call — never to make a red build green.
# See docs/analysis/plugin-definition-schema-evolution-wedge.md.
#
# requiredStoreDeclarations[].annotation is the field whose addition froze a plugin's
# registration for two days; it is listed because it is still a required scalar today.
