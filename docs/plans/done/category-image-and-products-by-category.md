# Category image, and products queryable by category

## Context

Two gaps in the `online-shop-hybrid` example, both about the **Category** entity:

1. **A category has no image.** `Product` has the full treatment — `@storageRef("productImages")`
   on `AddProduct` / `ChangeProductImage` / `ImportProduct` / `Products`, a real
   presign→PUT→serve upload loop in the seed, and a provisioned object store. `Category` has only
   `categoryId` / `name` / `archived`.

2. **Nothing can ask for a category's products.** `Catalog_Product` carries `categoryId`, but
   `Catalog_ProductFilter` offers only `ids` / `productIdEq` / `search`
   ([domain-api.graphql:156](../../examples/online-shop-hybrid/schema/domain-api.graphql#L156)), so
   the query a category detail page would need does not exist on either platform.

Investigation ruled out the annotation that looks purpose-built for the second gap.
**`@resolvesMany` is broken end to end**: the PPX writes `config.idsResolvers`, but nothing
anywhere emits the SDL virtual field. `GraphQL_FragmentGenerator` builds the object type from the
sury state schema alone
([:150-160](../../reventless/core/src/components/Api/GraphQL_FragmentGenerator.res#L150-L160)) and
`querySchemaEntry` has no channel for resolver configs
([Api.res:100-126](../../reventless/infra/src/components/Api.res#L100-L126)); the local adapter
drops both configs
([QueryDbResolvers_GraphQL.res:75-76](../../reventless/local/src/adapter/QueryDb/QueryDbResolvers_GraphQL.res#L75-L76));
and AWS attaches a resolver to a field *and a type name* that do not exist — `~type_=name` is the
capitalised spec name, not the plugin-prefixed `returnTypeName`
([QueryDbResolvers_AppSync.res:78](../../reventless/aws/src/adapter/QueryDb/QueryDbResolvers_AppSync.res#L78),
[:478](../../reventless/aws/src/adapter/QueryDb/QueryDbResolvers_AppSync.res#L478)). The
`reventless-gwt` `MakeResolver` DSL simulates the join in-memory against `config`, so GWT tests
pass green over the gap, and
[querydb-annotations-and-sort-key-queries.md:175](done/querydb-annotations-and-sort-key-queries.md#L175)
still has "Integration test: verify virtual field resolvable" unchecked. **Fixing `@resolvesMany`
is out of scope here** — it wants its own plan.

> Since fixed, end to end, in [cross-table-fields-end-to-end.md](cross-table-fields-end-to-end.md).
> The relation below is still served by the index, which is the right shape for a paginated,
> server-filtered product list; the annotation is for embedding a referenced row.

So the relation is served the other way round: index `Products.categoryId` so the server can
answer "products in this category".

**Outcome:** a category carries an image through the same upload loop products use, and the server
can answer a category's product list — server-filtered and paginated. Rendering that list on a
category detail page is client-side work, tracked separately in the UI repo; this plan lands the
contract it needs.

## Part A — Category image

Mirrors `Product` exactly: a new `categoryImages` object store, image settable at creation and
changeable afterwards.

### Catalog plugin — `examples/online-shop-hybrid/catalog/src/Category/`

| File | Change |
|---|---|
| `StateChangeSlice/AddCategory.res` | `@storageRef("categoryImages") imageUrl?: string` on the `AddCategory` command variant and the `CategoryAdded` event |
| `StateChangeSlice/AddCategory_Behavior.res` | thread `imageUrl` through `decide` |
| `StateChangeSlice/ChangeCategoryImage.res` | **new** — mirrors `Product/StateChangeSlice/ChangeProductImage.res` |
| `StateChangeSlice/ChangeCategoryImage_Behavior.res` | **new** — state `{exists, archived, currentImageUrl}`; `CategoryNotFound`, `CategoryAlreadyArchived`, `Ok([])` when the image is unchanged |
| `StateViewSliceStream/Categories.res` | `CategoryAdded` gains `imageUrl?`, new `CategoryImageChanged` consumed event, state gains `@storageRef("categoryImages") imageUrl?: string` |
| `StateViewSliceStream/Categories_Projection.res` | set on add, update on change |

`ChangeCategoryImage` carries `@authorize(AllowGroups(["Admin", "Merchandiser"]))`, matching the
other three category commands. Note `ChangeProductImage` does *not* check `archived`; every
category slice does (`CategoryAlreadyArchived` in `RenameCategory`), so follow the category
convention rather than the product one.

`src/Plugin.res` regenerates via `prebuild` → `generate-plugin src/`; `src/capabilities.json` via
`postbuild` → `emit-capabilities src/`. Neither is hand-edited.

### Platform

- `platform-aws/src/PlatformCapabilities.res` — regenerated by `pnpm run generate:platform` from
  `platform-aws/`; gains `ObjectStore({plugin: "Catalog", store: "categoryImages"})`.
- No local-platform change — stores register generically from the plugin structure
  ([Platform.res:923-932](../../reventless/local/src/Platform.res#L923-L932)).

### Seed — `examples/online-shop-hybrid/seed-data/src/`

- **`DemoData.res`** — `category` type gains `imageUrl: option<string>`; each of the 8 literals
  gets `imageUrl: None`, filled by the upload phase exactly as `product.imageUrl` is. Add
  `categorySvg(~name, ~index)` beside
  [productSvg](../../examples/online-shop-hybrid/seed-data/src/DemoData.res#L152-L160) — same
  deterministic hue-from-index SVG, different dimensions so the two are distinguishable on screen.
- **`HybridSeedData.res`** — `categoryImageStore = "Catalog.categoryImages"`;
  `uploadCategoryImages` mirroring
  [uploadProductImages](../../examples/online-shop-hybrid/seed-data/src/HybridSeedData.res#L67-L94)
  and honouring `connection.uploadsSkipped`; `seedCategories` passes `imageUrl`; a
  `ChangeCategoryImage` call in `seedCatalogEdits` so the change path is exercised alongside the
  existing rename/archive churn. Upload before `seedCategories`, as products already do in `run`.
- **`DemoCommands.res`** — `addCategory` gains the optional `imageUrl` arg with the same
  present/absent handling as
  [addProduct](../../examples/online-shop-hybrid/seed-data/src/DemoCommands.res#L59-L76); new
  `changeCategoryImage` encoder.
- **`Storefront.res`** — add `"ChangeCategoryImage"` to the `Merchandiser` journey's `commands`.

### Tests — `examples/online-shop-hybrid/catalog/tests/Category/`

Example plugins ship only `_GWT.res` tests, mirroring `src/` 1:1.

- `StateChangeSlice/AddCategory_GWT.res` — extend with an image-carrying case.
- `StateChangeSlice/ChangeCategoryImage_GWT.res` — **new**: happy path, `CategoryNotFound`,
  `CategoryAlreadyArchived`, and the idempotent unchanged-image case returning no events.
- `StateViewSliceStream/Categories_GWT.res` — extend for `imageUrl` on add and for
  `CategoryImageChanged`.

`.gwt.json` siblings are gitignored build output.

## Part B — Products queryable by category

`examples/online-shop-hybrid/catalog/src/Product/StateViewSliceStream/Products.res`:

```rescript
@index categoryId: string,
```

Verbatim the example the PPX guide uses
([reventless-ppx.md:570-580](../../packages/doc/docs-app/reventless-ppx.md#L570-L580)). It yields,
on **both** platforms:

- `categoryIdEq: ID` on `Catalog_ProductFilter` and `categoryId` on `Catalog_ProductOrderField` —
  `deriveServerCapability` pushes indexed fields into `filterFields`/`sortFields`
  ([GraphQL_FragmentGenerator.res:307-310](../../reventless/core/src/components/Api/GraphQL_FragmentGenerator.res#L307-L310))
- a `Catalog_ProductByCategoryId` index query
  ([PluginBaseFragment.res:40](../../reventless/core/src/plugin/api/PluginBaseFragment.res#L40);
  local resolver with real index lookup, scan fallback and owner scoping at
  [QueryDbResolvers_GraphQL.res:609](../../reventless/local/src/adapter/QueryDb/QueryDbResolvers_GraphQL.res#L609))
- `x-reventless-index: true` on the field's JSON Schema
  ([SuryToJsonSchema.res:48-54](../../reventless/core/src/components/Api/SuryToJsonSchema.res#L48-L54))
  — the signal a shell reads to discover that the server can answer this filter
- on AWS, a GSI on the Products table. **Flag:** adding a GSI to a live table is an update, not a
  create; on `alpha` the wipe-and-reseed path is cheaper than waiting on a backfill.

The paginated, owner-aware **connection filter** is the intended consumer surface; the
`ByCategoryId` index query returns a bare list.

Goldens: `pnpm run check:graphql:update` — the diff is the review artifact and belongs in this
commit.

## Verification

**Build and unit**
```bash
pnpm run build 2>&1 | grep -E "Warning|warning|error|Error"   # must be empty
pnpm run test:file examples/online-shop-hybrid/catalog/tests/Category
pnpm run check:graphql          # expect drift; then :update and read the diff
```

The `domain-api.graphql` diff should show exactly: `imageUrl` on `Catalog_Category`,
`categoryIdEq` on `Catalog_ProductFilter`, `categoryId` in `Catalog_ProductOrderField`, a
`Catalog_ProductByCategoryId` query, and the changed `Catalog_AddCategory` / new
`Catalog_ChangeCategoryImage` mutations. Anything else is a surprise worth chasing.

**Seed round-trip** (from `examples/online-shop-hybrid/platform-local/`)
```bash
pnpm run serve:reset &          # fresh sqlite
pnpm run seed                   # the sample set is enough
```

Confirm the run reports `category images: 8 uploaded`, then exercise both new surfaces:

```bash
curl -s localhost:4000/graphql -H 'content-type: application/json' \
  -d '{"query":"{ Catalog_Categories(first:3){edges{node{categoryId name imageUrl}}} }"}'
curl -s localhost:4000/graphql -H 'content-type: application/json' \
  -d '{"query":"{ Catalog_Products(filter:{categoryIdEq:\"cat-01\"},first:5){edges{node{productId name categoryId}}} }"}'
```

The second must return only `cat-01` products. `curl -I` the returned `imageUrl` path to confirm
the bytes actually serve.

**Regression:** `pnpm test` and `pnpm run test:projects` at the repo root.
