## Goal

Add missing E2E tests to `reventless/reventless-in-memory/tests/E2E/`. Each component gets its
own subfolder. The aggregate tests have already been moved to `tests/E2E/aggregate/`.
The following builders have no E2E coverage:

## Key Patterns

### Async test binding
All new tests must use `open AsyncTest` + `open AsyncTest.Expect` (NOT `open Jest`).
`AsyncTest.testPromise` binds directly to Jest's `test` (properly awaits async functions).
The existing `AggregateE2ETest.res` accidentally works with the broken `testPromise` from
`open Jest`; new tests should not repeat this pattern.

### File layout
Each component gets its own subfolder under `tests/E2E/<component>/` with two files:
- `<Component>E2EFixtures.res` — specs, behaviors, bus setup, shared instances
- `<Component>E2ETest.res` — test cases using the fixtures

### Standard setup sequence
1. `module Bus = InMemory_Bus.Make()` — isolated bus per test file
2. Subscribe to topics BEFORE building any component
3. `TestRunner.setup()` BEFORE any `Component.make`
4. Build component instances at module top level (shared across tests)
5. For DCB: `beforeAllAsync` to force Output chain resolution
6. `beforeEach` to reset `capturedEventCount` counters

## Step 1: DcbE2E (DcbEventLog + StateChangeSlice)

**Files to create:**
- `tests/E2E/dcb/DcbE2EFixtures.res`
- `tests/E2E/dcb/DcbE2ETest.res`

**Covers:** `DcbEventLog_Builder`, `StateChangeSlice_Builder`

### Minimal spec

`DcbE2EFixtures.res` defines an inline minimal spec:

```rescript
// DcbEventLog spec
module ItemEventLog = {
  @schema
  type event = | ItemAdded({id: string, name: string})
}

// StateChangeSlice spec
module AddItemSpec: ReventlessSpec.StateChangeSlice.Spec = {
  let name = "AddItem"
  module DcbEventLogSpec = ItemEventLog

  @schema type command = | AddItem({id: string, name: string})
  @schema type error = | ItemAlreadyExists

  type decisionModel = bool   // true = item exists
  let initialDecisionModel = false

  let reduce = (_model, _event) => true  // any event means item exists

  let decide = (model, command) =>
    if model {
      Error(ItemAlreadyExists)
    } else {
      switch command {
      | AddItem({id, name}) => Ok([ItemEventLog.ItemAdded({id, name})])
      }
    }

  let commandSchema = commandSchema  // auto-generated by @schema
}
```

### Bus setup

```rescript
module Bus = InMemory_Bus.Make()

// Topic name = DcbEventLog name ++ "EventTopic" = "ItemEventLogEventTopic"
let capturedEventCount: ref<int> = ref(0)
let _ = Bus.subscribeToEvents("ItemEventLogEventTopic", async (_, _, _) => {
  capturedEventCount := capturedEventCount.contents + 1
})

let _ = TestRunner.setup()
```

### DcbEventLog and StateChangeSlice wiring

```rescript
module DcbEventLogMaker = DcbEventLog_Builder.Make(Bus)
module ItemEventLogMaker = DcbEventLogMaker.Make(ItemEventLog)
let eventLog = ItemEventLogMaker.make(~name="ItemEventLog")

module AddItemMaker = StateChangeSlice_Builder.Make(AddItemSpec)

// publishJsons routing — same pattern as examples/dcb
let publishJsons: ReventlessSpec.CommandTopic.publishJsons = async cmdJsons => {
  let _ = await cmdJsons
  ->Array.map(async cmdJson => {
    let typeName = switch cmdJson.commandJson {
    | JSON.Object(dict) =>
      dict->Dict.get("TAG")
      ->Option.flatMap(j => switch j { | JSON.String(s) => Some(s) | _ => None })
      ->Option.getOr("")
    | _ => ""
    }
    let fullBody = JSON.Encode.object(Dict.fromArray([
      ("id", JSON.Encode.string(cmdJson.id)),
      ("meta", cmdJson.meta->S.reverseConvertToJsonOrThrow(ReventlessSpec.Message.metaSchema)),
      ("command", cmdJson.commandJson),
    ]))
    let handlers = CommandTopic.getHandlers(typeName)
    let _ = await handlers
    ->Array.map(async entry => {
      let _ = await entry.handler([{CommandTopic.reference: cmdJson.id, command: fullBody}])
    })
    ->Promise.all
  })
  ->Promise.all
}

let publishJsonsOutput = publishJsons->Pulumi.Output.make

let _addItemSlice = AddItemMaker.make(~dcbEventLog=eventLog, ~publishJsons=publishJsonsOutput)

let testMeta: ReventlessSpec.Message.meta = {
  service: "test",
  time: "2024-01-01T00:00:00.000Z",
  ip: "127.0.0.1",
  user: "testuser",
  msgId: "msg-001",
  correlationId: "corr-001",
}

let dispatch = async (commandJson, id) =>
  await publishJsons([{ReventlessSpec.Message.id, meta: testMeta, commandJson}])
```

### Test cases in `DcbE2ETest.res`

```
describe("DcbEventLog E2E", () => {
  beforeAllAsync: force Output resolution via TestRunner.resolve on eventLog.operations
  beforeEach: capturedEventCount := 0

  1. "AddItem command publishes 1 event to event topic"
     → dispatch AddItem → expect capturedEventCount = 1

  2. "duplicate AddItem produces 0 events (ItemAlreadyExists)"
     → dispatch same id again → expect capturedEventCount = 0

  3. "AddItem for new id produces 1 event"
     → dispatch new id → expect capturedEventCount = 1

  4. "direct read of DcbEventLog returns appended events"
     → resolve eventLog.operations → call ops.read({}) → check events count > 0

  5. "direct read with tag filter returns only matching events"
     → call ops.read({query: [{eventTypes: ["ItemAdded"]}]}) → verify events
})
```

**Note on `commandSchema`:** The `@schema`-generated schema for the command type is named
`commandSchema` (since the type is `command`). Same for `errorSchema`. The DcbEventLog event
schema is `schema` (since the type is `t`... no wait, it's `event`). For a named type `event`,
the generated schema is `eventSchema`.

## Step 2: ReadModelE2E

**Files to create:**
- `tests/E2E/readmodel/ReadModelE2EFixtures.res`
- `tests/E2E/readmodel/ReadModelE2ETest.res`

**Covers:** `ReadModel_Builder`

### Key implementation question

`ReadModel_Builder.Make(Bus).Make(Spec, Mappings).make` requires:
- `~api: unit` (in-memory)
- `~apiRole: unit` (in-memory)
- `~allEventTopics: ReventlessSpec.EventTopic.allOutputs`

`allEventTopics` is a `dict<ReventlessSpec.EventTopic.outputs>` keyed by topic name.
`EventTopic.outputs = { resources: array<Adapter.resource> }` where
`Adapter.resource = { name: Pulumi.Output.t<string>, type_?: string }`.

**Approach:** We don't need an actual Aggregate to test ReadModel. Construct `allEventTopics`
manually from a known topic name and publish events directly via `Bus.publishEvent`.

```rescript
let topicName = "TestItemAggrEventTopic"
let topicResource: ReventlessSpec.Adapter.resource = {
  name: Pulumi.Output.make(topicName),
}
let allEventTopics = Dict.fromArray([
  (topicName, {ReventlessSpec.EventTopic.resources: [topicResource]}),
])
```

### Minimal spec

```rescript
// Minimal ReadModel state
module ItemReadModelSpec: ReventlessSpec.ReadModel.Spec = {
  module Id = ReventlessSpec.Id.String
  let name = "TestItemReadModel"

  @schema
  type state = { name: string }

  // Minimal config (no real GraphQL resolvers needed in-memory)
  let config: ReventlessSpec.ReadModel.config = {
    indexes: [],
    resolvers: [],
  }

  let subIdConfig = None
}

// Minimal mapping: ItemCreated → creates ReadModel state
module ItemMapping: ReventlessSpec.Projection.Mapping = {
  module SourceId = ReventlessSpec.Id.String
  @schema type sourceEvent = | ItemCreated({name: string})
  @schema type targetState = { name: string }

  let map = (event: ReventlessSpec.Message.event'<string, sourceEvent>) =>
    switch event.payload {
    | ItemCreated({name}) => Projection.Create(event.id, {name: name})
    }

  let sourceEventSchema = sourceEventSchema
  let sourceName = "TestItemAggrEventTopic"   // matches the topic we publish to
  let subIdConfig = None
  let targetStateSchema = targetStateSchema
}
```

**Note on Mappings module type:** Check `ReventlessSpec.Projection.Mappings` to see how to
construct an array of Mapping modules. May be `module Mappings = { let mappings = [module(ItemMapping)] }` or similar.

### ReadModel wiring

```rescript
module ReadModelMaker = ReadModel_Builder.Make(Bus)
module ItemReadModel = ReadModelMaker.Make(ItemReadModelSpec, ItemMappings)
let rm = ItemReadModel.make(~api=(), ~apiRole=(), ~allEventTopics)
```

### Accessing projected state

To query the projected state, use `rm->ItemReadModel.operations->TestRunner.resolve` and
call the query operations. If ReadModel's operations expose a `query` function, use that.
Alternatively, access QueryDbStorage_InMemory directly if operations are not exposed.

**Need to verify:** What operations does `ReadModel.operations` expose? Check
`ReventlessSpec.ReadModel.operations` type.

### Test cases in `ReadModelE2ETest.res`

```
describe("ReadModel E2E", () => {
  beforeAllAsync: ensure EventCollectorChannel subscription is ready
    (resolve Output chain by awaiting resource.name from allEventTopics)

  beforeEach: (no shared state to reset — each test may use fresh bus)

  1. "ItemCreated event projects into ReadModel state"
     → publish ItemCreated event to bus topic → await → query ReadModel → verify state

  2. "query for unknown ID returns no state"
     → query ReadModel for unknown id → verify None/empty

  3. "multiple events project and override state"
     → publish ItemCreated → publish update event → query → verify latest state
})
```

**Important:** After calling `EventCollectorChannel.connect`, there are 2 async microtask ticks
before the subscription is registered (due to `Output.apply`). Use an extra `await` before
publishing — e.g., `let _ = await topicResource.name->TestRunner.resolve`.

## Step 3: StateViewSliceE2E

**Files to create:**
- `tests/E2E/stateviewslice/StateViewSliceE2EFixtures.res`
- `tests/E2E/stateviewslice/StateViewSliceE2ETest.res`

**Covers:** `StateViewSlice_Builder`

### Approach

StateViewSlice connects to a DcbEventLog and projects its events into a QueryDb.
The test reuses the `ItemEventLog` spec from DcbE2EFixtures (same event type).

**Option A:** Share a new Bus+DcbEventLog+StateChangeSlice+StateViewSlice in fixtures.
**Option B:** Reuse DcbE2EFixtures modules directly (if module-level sharing works).

Prefer **Option A** — isolated bus/state per fixture file avoids cross-test interference.

### Minimal StateViewSlice spec

```rescript
// StateViewSlice spec: project ItemAdded events into a {name: string} state
module ItemViewSpec: ReventlessSpec.StateViewSlice.Spec = {
  let name = "ItemView"
  module DcbEventLogSpec = ItemEventLog2  // same event type as Step 1

  @schema type event = ItemEventLog2.event
  @schema type state = { name: string }

  let project = (currentState, event) =>
    switch event {
    | ItemEventLog2.ItemAdded({id, name}) =>
      switch currentState {
      | None => [Projection.Create(id, {name: name})]
      | Some(_) => [Projection.Update(id, _ => {name: name})]
      }
    }
}
```

**Note:** StateViewSlice has `@schema type event` which must be the same variant as
`DcbEventLogSpec.event`. The StateViewSlice Builder wires up subscriptions to the DcbEventLog's
event topic automatically — it doesn't need `allEventTopics` manually.

### Wiring

```rescript
module Bus = InMemory_Bus.Make()
let _ = TestRunner.setup()

// Reuse DcbEventLog + StateChangeSlice from Step 1 pattern for the command side
module DcbEventLogMaker = DcbEventLog_Builder.Make(Bus)
module ItemEventLogMaker2 = DcbEventLogMaker.Make(ItemEventLog2)
let eventLog2 = ItemEventLogMaker2.make(~name="ItemEventLog2")

// StateChangeSlice for writing
module AddItemMaker2 = StateChangeSlice_Builder.Make(AddItemSpec2)
let _slice2 = AddItemMaker2.make(~dcbEventLog=eventLog2, ~publishJsons=publishJsonsOutput2)

// StateViewSlice for reading (takes dcbEventLog, creates its own QueryDb)
module ItemViewMaker = StateViewSlice_Builder.Make(ItemViewSpec)
let itemView = ItemViewMaker.make(~dcbEventLog=eventLog2)
```

### Querying StateViewSlice

StateViewSlice `outputs` has `queryDb: QueryDb.outputs`. To query projected state, resolve
the QueryDb operations and call its query function.

**Need to verify:** How to extract queryDb from `StateViewSlice.outputs` and whether

## Step 4: CounterE2E (Medium Priority)

**Files to create:**
- `tests/E2E/counter/CounterE2EFixtures.res`
- `tests/E2E/counter/CounterE2ETest.res`

**Covers:** `Counter_Builder`

### How Counter works

`Counter.make` takes `~name`, `~counterEventsHandler`, and optional `~ttl`.
The `counterEventsHandler` subscribes to events and returns count increments.
Operations:
- `count(items: array<countItem>)` — increments counts
- `addToCounterTarget(ref)` — registers a target counter reference

For E2E test, we can:
1. Create a Counter with a mock `counterEventsHandler`
2. Directly call `count([{counterId: "c1", reference: "ref-1", inc: 1}])`
3. Query the counts via the Counter's QueryDb operations

**Need to verify:** What operations does `Counter.operations` expose? How to query counts?

### Test cases in `CounterE2ETest.res`

```
describe("Counter E2E", () => {
  1. "count increments the counter"
     → call ops.count → verify counter value

  2. "addToCounterTarget registers a target"
     → call ops.addToCounterTarget → verify via query

  3. "deduplication: same reference counted only once"
     → call count twice with same reference → verify count = 1
})
```

## Implementation Notes

### `open` pattern for new tests
```rescript
open AsyncTest
open AsyncTest.Expect
// NO: open Jest
// NO: open Expect  (from rescript-jest)
```

### DCB `commandSchema` name
For a spec type `@schema type command`, the generated schema is `commandSchema`.
For `@schema type event`, it's `eventSchema`. For the top-level `type t`, it's `schema`.

### `beforeAllAsync` for DCB tests
Required to force the `Output.apply` chain to run so StateChangeSlice handlers are
registered before the first test:
```rescript
let _ = beforeAllAsync(async () => {
  let _ = await eventLog->EventLogMaker.operations->TestRunner.resolve
})
```

### Checking AggregateE2ETest
`AggregateE2ETest.res` uses the broken `testPromise` from `open Jest`. This is a known issue
(see MEMORY.md). It accidentally passes due to test 2 expecting count=0. Consider migrating
it to `AsyncTest.testPromise` as part of this work, but do so in a separate commit to keep
changes focused.

### Topic name derivation
- Aggregate event topic: `Spec.name ++ "Aggr" ++ "EventTopic"` (e.g., "TestItemAggrEventTopic")
- DcbEventLog event topic: `name ++ "EventTopic"` (e.g., "ItemEventLogEventTopic")
