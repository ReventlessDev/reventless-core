# Resource Tags in Resource Record

## Context

AWS resource tags are generated by `AWS_Tags.make` and applied at Pulumi resource creation time,
but they are never captured in the `resource` / `resolvedResource` / interop `Resource.t` records.
Adding a `tags` field makes tags available at runtime and in stack exports (e.g. for observability tooling or MCP).

## Step 1 — `reventless-infra/src/adapter/Adapter.res`

Add `tags` to both `resource` and `resolvedResource`, and to `make`:

```rescript
// resource record — new field:
tags: Pulumi.Output.t<dict<string>>,

// resolvedResource record — new field:
tags: dict<string>,

// make — new optional param with empty-dict default:
~tags=Dict.make()->Pulumi.Output.make,
```

## Step 2 — `reventless-interop/src/Resource.res`

```rescript
@schema
type t = {
  ...
  configuration: dict<string>,
  tags: dict<string>,   // new
}
```

## Step 3 — `Util_DynamoDb.res` — `toResource`

**The `PulumiAws.DynamoDb.Table.t` output type does not include a `tags` field** — tags only appear
in the args (input) type. Tags cannot be read back from the created resource.

`toResource` is called from the storage adapter builders (e.g. `EventLogStorage_DynamoDb.res`)
which also call `makeTable`. The tags must be threaded through from the call site.

Update `toResource` to accept tags as an explicit parameter:

```rescript
let toResource: (~tags: Pulumi.Output.t<dict<string>>=?, table) => resource = (~tags=?, {id, name, arn} as table) =>
  make(
    ~name,
    ~id,
    ~urn=arn,
    ~service=name->Pulumi.Output.apply(_ => AWS.DynamoDb.service),
    ~resourceInfo=table->toResourceInfo,
    ~resourceType="aws:dynamodb:Table"->Pulumi.Output.make,
    ~tags=?tags,
  )
```

Then update all callers of `Util_DynamoDb.toResource` to pass the tags they already have.

## Step 4 — Remaining `Util_*.toResource` helpers

Same situation: no Pulumi resource type in the bindings exposes `tags` as an output field.
Tags must be threaded from the call site in the same way as Step 3.

For this plan, update all `toResource` helpers that are called from sites where tags are
already available (i.e. sites that call `AWS_Tags.make`). The default `Dict.make()` applies
where tags are genuinely absent.

Affected files:
- `Util_SQS.res`, `Util_SQS_FIFO.res`
- `Util_SNS.res`, `Util_SNS_FIFO.res`
- `Util_S3.res`, `Util_Lambda.res`
- `Util_AppSync.res`, `Util_Cloudwatch.res`, `Util_IAM_Role.res`
- `Util_EventSourceMapping.res`, `Util_DynamoDbStream.res`

Check each caller to decide whether tags are available to pass through.

## Step 5 — `reventless-interop/tests/ResolvedOutputsTest.res`

Add `tags: Dict.make()` to any fixture that constructs a `Resource.t` literal.
