# Behaviour → Behavior Rename Implementation Plan

## Executive Summary

This plan outlines a complete transition from British spelling "Behaviour" to American spelling "Behavior" across the entire Reventless codebase, including:
- Source code files (.res, .js)
- Documentation (.md)
- Configuration files (CSS, JSON)
- Code generator templates (.hbs)
- Test files

**Scope:** 100+ files with 200+ individual occurrences

**Breaking Change:** Yes - this is a major API-breaking change requiring version bump

**IMPORTANT:** All capitalization patterns will be preserved:
- `Behaviour` → `Behavior` (PascalCase - used in module names, types)
- `behaviour` → `behavior` (lowercase - used in prose, comments, file paths)

## Capitalization Guidelines

### PascalCase (Module/Type Names)
- **Pattern:** `Behaviour` → `Behavior`
- **Usage:** Module names, type names, functor parameters
- **Examples:**
  - `module Behaviour = ...` → `module Behavior = ...`
  - `Behaviour.T` → `Behavior.T`
  - `PluginBehaviour` → `PluginBehavior`

### lowercase (File Paths, Prose, Comments)
- **Pattern:** `behaviour` → `behavior`
- **Usage:** File paths in templates, documentation prose, comments
- **Examples:**
  - `CustomerBehaviour.res` → `CustomerBehavior.res` (PascalCase in filename)
  - File path references: `{{properCase aggregateName}}Behaviour.re` → `{{properCase aggregateName}}Behavior.re`
  - Documentation: "aggregate behaviour" → "aggregate behavior"
  - Comments: "// behaviour module" → "// behavior module"

## File Naming Conventions

### ReScript Source Files
- **Pattern:** `[ModuleName].res` where ModuleName is PascalCase
- **Example:** `Behaviour.res` → `Behavior.res`
- **Compound names:** `PluginBehaviour.res` → `PluginBehavior.res`

### Test Helper Files
- **Pattern:** `[ModuleName]Test.res`
- **Example:** `BehaviourTest.res` → `BehaviorTest.res`

### Template Files
- **Pattern:** `[ComponentName].re.hbs` or descriptive name
- **Example:** `Behaviour.re.hbs` → `Behavior.re.hbs`
- **Action templates:** Keep descriptive names like `addStatusToBehaviourApply.re.hbs` → `addStatusToBehaviorApply.re.hbs`

## Risk Assessment & Mitigation

### High Risk Areas

#### 1. Breaking API Changes
**Risk:** External code depending on `Behaviour` module will break

**Mitigation:**
- This is a major version change
- Create comprehensive migration guide
- Consider deprecation warnings in previous version if possible
- Update CHANGELOG.md with clear breaking change notice

#### 2. Build System Dependencies
**Risk:** ReScript compiler may have issues with renamed files

**Mitigation:**
- Clean build before and after changes: `npm run clean && npm run build`
- Verify rescript.json doesn't have explicit file listings
- Test incremental builds during development

#### 3. Template Generation
**Risk:** Plop generators may create files with wrong naming

**Mitigation:**
- Test all plop generators after updates
- Verify generated code compiles
- Update plop tests if they exist

### Medium Risk Areas

#### 4. Documentation Search/Links
**Risk:** Internal documentation links may break

**Mitigation:**
- Search for `#behaviour` anchor links
- Update all cross-references
- Test documentation site navigation

#### 5. IDE/Editor Integration
**Risk:** Language server may need restart to recognize renamed modules

**Mitigation:**
- Document need to restart ReScript LSP
- Include in migration notes

### Low Risk Areas

#### 6. Git History
**Risk:** File rename may obscure git blame history

**Mitigation:**
- Using IDE/git tools that support following renames
- Ensure rename is atomic (done in same commit)
- Use `git mv` if executing via terminal (maintains history)

## Migration Guide (For Framework Users)

### Breaking Changes in [Version X.0.0]

The `Behaviour` module has been renamed to `Behavior` (American spelling) throughout the framework.

#### Required Code Changes

**1. Module Imports (PascalCase)**
```rescript
// Before
module MyBehaviour: Reventless.Behaviour.T = { ... }

// After
module MyBehavior: Reventless.Behavior.T = { ... }
```

**2. File Names (PascalCase)**
```
// Before
src/Aggregates/Customer/CustomerBehaviour.res

// After
src/Aggregates/Customer/CustomerBehavior.res
```

**3. Aggregate Builder Parameters (PascalCase)**
```rescript
// Before
module CustomerAggregate = AggregateBuilder.Make(
  Config,
  Customer,
  Customer_Behaviour,  // ← Change this (PascalCase)
  Customer_EventMappings,
)

// After
module CustomerAggregate = AggregateBuilder.Make(
  Config,
  Customer,
  Customer_Behavior,  // ← To this (PascalCase)
  Customer_EventMappings,
)
```

**4. Type Constraints (PascalCase)**
```rescript
// Before
module Make = (Behaviour: Behaviour.T with module Spec := Spec) => { ... }

// After
module Make = (Behavior: Behavior.T with module Spec := Spec) => { ... }
```

**5. Documentation Text (lowercase)**
```markdown
<!-- Before -->
The aggregate behaviour defines business logic...

<!-- After -->
The aggregate behavior defines business logic...
```

**6. Comments (lowercase)**
```rescript
// Before: Initialize behaviour state
let init = ...

// After: Initialize behavior state
let init = ...
```

#### Automated Migration

**CRITICAL:** Preserve capitalization during search and replace:

1. **Case-sensitive replace for PascalCase** (code/modules/types):
   - Search: `\bBehaviour\b` (case-sensitive, word boundary)
   - Replace: `Behavior`
   - Files: `*.res`, `*.re`, `*.js` (code files)

2. **Case-sensitive replace for lowercase** (prose/comments):
   - Search: `\bbehaviour\b` (case-sensitive, word boundary)
   - Replace: `behavior`
   - Files: `*.md`, `*.res`, `*.re` (documentation and comments)

3. **File renames** (maintain PascalCase pattern):
   - Pattern: `*Behaviour.res` → `*Behavior.res`
   - Pattern: `*Behaviour.re.hbs` → `*Behavior.re.hbs`

**Verification:** After replacement, manually check mixed-case contexts to ensure proper capitalization.
