# reventless-in-memory: Implementation Plan & Status

*Status: COMPLETE — all 9 tests passing*

## Goal

Add a new Lerna package `reventless-in-memory` that implements `ReventlessSpec.Platform.T` using only in-memory data structures, enabling full E2E testing of aggregates without AWS or a live Pulumi stack.

---

## Architecture

### Core Design

Every test creates a fresh `InMemory_Bus.Make()` to isolate state. The bus provides:
- **Event fan-out**: `publishEvent(topic, service, meta, json)` → `subscribeToEvents(topic, fn)`
- **Command dispatch**: `dispatchCommand(channel, json)` → `registerCommandHandler(channel, fn)`
- **`reset()`**: clears all handlers for cleanup

Tests subscribe to the Bus BEFORE wiring components, then use `Aggregate_Builder.Make(Bus)` directly (not `Platform.Make`) to get full control over the bus reference.

### Pulumi Mock Mode

All component builders create Pulumi `ComponentResource` instances. In tests, call `TestRunner.setup()` ONCE before any `Component.make` to activate `pulumi.runtime.setMocks`. This makes the `ComponentResource` constructor work (intercepts gRPC calls) and makes `Pulumi.Output.apply` resolve synchronously. Use `TestRunner.resolve(output)` to get a promise from any `Output.t`.

### Critical: `Component.js` in `reventless-spec`

`packages/reventless-spec/src/components/Component.js` is a HAND-WRITTEN file (not ReScript generated) providing `class Component extends pulumi.ComponentResource`. **If a rescript CJS build runs in that package, it will overwrite this file** — the ReScript compiler generates a broken circular `require("./Component").default` that returns `undefined`.

The correct `Component.js` must export:
- `exports.default = Component` (the class)
- `exports.make = make` (the constructor wrapper)
- All other ReScript-generated utility functions (`setOutputs`, `outputs`, `registerOutputs`, `wrappedOutputs`, `setOperations`, `operations`, `toPulumiResource`, `fromPulumiResource`)

**Prevention / Mitigation**: The root `rescript.json` propagates its `"module": "esmodule"` / `"suffix": ".res.mjs"` to all packages in its `dependencies` list when built from the root (`npm run build`). This produces `.res.mjs` output only — `Component.js` is never touched by the root build. However, a `rescript clean && rescript build` inside `packages/reventless-spec/` WILL regenerate `Component.js` with a broken circular-require. Recovery: `git checkout packages/reventless-spec/src/components/Component.js`.

**`Component.js` export style for ESM compatibility**: Must use `module.exports = Component` (class as primary export), not `exports.default = Component`. ESM `import Component from "./Component"` (generated by ReScript from `@new ... = "default"`) gets `module.exports`, not `exports.default`. Named utility exports are added as properties: `module.exports.make = make`, `module.exports.setOutputs = setOutputs`, etc.

## Command Topic Encoding (CRITICAL)

`CommandTopicChannel_InMemory` must encode commands as the **full message body**:
```json
{"id": "<aggregateId>", "meta": {...}, "command": <commandPayload>}
```
NOT just the command payload. `CommandTopic_Callback.handleJsonCommands` calls `Message.decodeCommand'` which decodes the full `{id, meta, command}` structure.

The `reference` field in `topicItem` is also set to the aggregate id (extracted from the body's `"id"` field).

## Jest Configuration

The package uses CJS Jest (no `--experimental-vm-modules`). Key issues and solutions:

1. **`@npmcli/arborist` missing**: Pulumi's `runtime/closure/codePaths.js` imports it, but it's in `@pulumi/pulumi/node_modules/` not root. Mock it with `emptyModule.js` via `moduleNameMapper`.

2. **`spdx-*` modules missing**: Similar transitive dependency issue. Map via `moduleNameMapper` pointing to root `node_modules/`.

3. **Component.js circular**: See above — must use the combined hand-written + ReScript-functions file.

Jest config in `package.json`:
```json
"jest": {
  "testMatch": ["<rootDir>/tests/**/*Test.js"],
  "moduleFileExtensions": ["js"],
  "modulePaths": ["<rootDir>/../../node_modules/@pulumi/pulumi/node_modules"],
  "moduleNameMapper": {
    "^@npmcli/arborist$": "<rootDir>/__mocks__/emptyModule.js",
    "^spdx-license-ids$": "<rootDir>/../../node_modules/spdx-license-ids/index.json",
    "^spdx-license-ids/deprecated$": "<rootDir>/../../node_modules/spdx-license-ids/deprecated.json",
    "^spdx-exceptions$": "<rootDir>/../../node_modules/spdx-exceptions/index.json"
  }
}
```

## Topic Name Derivation

For `Spec.name = "TestItem"`, the event topic name is:
```
Spec.name ++ "Aggr" ++ "EventTopic" = "TestItemAggrEventTopic"
```

This is computed by:
1. `Aggregate_Builder` constructs the aggregate with name `"TestItemAggr"` (`Spec.name + ComponentType.toName(Aggregate)`)
2. `EventLog_Builder` creates EventTopic with name `"TestItemAggrEventTopic"` (`aggrName + ComponentType.toName(EventTopic)`)

In `EventTopicPublisher_InMemory`, the bus key for events = the `~name` argument passed to `Publisher.make`.

## Test Usage Pattern

```rescript
// Create bus externally (to subscribe before wiring)
module Bus = InMemory_Bus.Make()

// Subscribe to events BEFORE creating components
let eventCount: ref<int> = ref(0)
let _ = Bus.subscribeToEvents("MySpecAggrEventTopic", async (_, _, _) => {
  eventCount := eventCount.contents + 1
})

// Activate Pulumi mock mode BEFORE component creation
let _ = TestRunner.setup()

// Build aggregate using the Bus
module AggMaker = Aggregate_Builder.Make(Bus)
module MyAgg = AggMaker.Make(MySpec, MyBehavior, Reventless.NoEventMappings.Make(MySpec))
let agg = MyAgg.make(~api=())

// In tests: resolve operations, publish commands, assert
let ops = await agg->MyAgg.operations->TestRunner.resolve
await ops.publishJsons([{id: "id-1", meta: testMeta, commandJson: cmdJson}])
expect(eventCount.contents)->toBe(1)
```
